# project-check: 合格条件で検査する

検査の対象・合格条件: $ARGUMENTS

この手順では検査と報告だけを行い、ファイルを修正しない。修正は利用者の指示を受けてから行う。

## 1. 合格条件を決める

- 引数に合格条件があればそれを使う。なければ `docs/ai/checks.md` から、差分に該当する作業の種類を選ぶ。
- 選んだ合格条件を、検査の前に箇条書きで示す。途中で条件を緩めない。

## 2. 差分と元資料を集める

- `git status` と `git diff`（必要なら `git diff --stat`）で変更の範囲を確かめる。
- 依頼内容や `tasks/active.md` と照らして、依頼外の変更がないかを見る。
- 判断の根拠になる元資料（`README.md`、元コード、既存の画面の文言など）を読む。

## 3. ファイルを書き換えない検査を実行する

該当するものだけ実行する。

- `node --check line-cm-helper.source.js`
- `node --check build-bookmarklet.mjs`
- `git diff --no-index --quiet -- index.html ブックマーク登録用.html`（終了コード 0 なら一致）
- `node .claude/hooks/check-claude-setup.mjs`（AI 作業設定を変えた場合）

`node build-bookmarklet.mjs` はファイルを上書きするため、この手順では実行しない。

## 4. 独立した確認を頼む

- サブエージェント `project-reviewer` に、合格条件、差分（`git diff` の出力）、元資料のパス、手順3の検査結果を渡す。
- `project-reviewer` はコマンドを実行できない。検査結果は主担当が渡す。
- 起動できない場合は、主担当が「依頼外の変更」「根拠のない記述」「合格条件の漏れ」の観点に切り替えて確かめ、報告に「独立レビュー未実施」と書く。

## 5. 報告する

次の形で報告する。

| 合格条件 | 結果（成功・失敗・未実行） | 証拠（コマンドと出力、ファイルと行） |
| --- | --- | --- |

続けて次を書く。

- 指摘事項: 対象の箇所、理由、重大度
- 未確認事項: エージェントでは確かめられないこと（実ブラウザでの動作など）と、利用者の確認手順
- 依頼外の変更の有無

公開・送信・push は、この手順に含まれない。
