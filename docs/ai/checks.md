# 合格条件と検査方法（checks）

作業の種類ごとの合格条件です。検査結果は「成功・失敗・未実行」に分けて報告します。
「未実行」を「成功」に含めないでください。合格条件を作業の途中で緩めないでください。

## 1. ブックマークレットの変更（`line-cm-helper.source.js`）

合格条件:

- [ ] `node --check line-cm-helper.source.js` が終了コード 0 で終わる
- [ ] 生成物3ファイル（`.txt`、`index.html`、`ブックマーク登録用.html`）が、同じ変更の中で生成し直されている
- [ ] `git diff --no-index --quiet -- index.html ブックマーク登録用.html` が終了コード 0（2つのHTMLが一致）
- [ ] 生成物の `.txt` が `javascript:` で始まる
- [ ] 生成時に terser を使えたか、簡易圧縮になったかを報告している
- [ ] LINE 側の保存・リクエスト・申請ボタンを押す処理を追加していない
- [ ] 保存キー、クリップボードの接頭辞（`LINE_CM_HELPER:`、`LINE_CM_TAG_JSON:`）を変えていない。変えた場合は利用者の承認がある
- [ ] 利用者から見た動作が変わる場合、`README.md` を更新している

手動確認（利用者が実ブラウザで行う）:

1. 切り出しくんの画面でブックマークレットを実行し、「このページから取得」で4項目（絵文字は番号も）を取れる
2. LINE Creators Market の表示情報画面で、英語欄と日本語欄に貼り付けられる
3. 保存・リクエスト・申請ボタンが自動で押されない
4. 変更した機能について、PC とスマホのどちらで確認したかを記録する

## 2. 生成スクリプトの変更（`build-bookmarklet.mjs`）

- [ ] `node --check build-bookmarklet.mjs` が終了コード 0
- [ ] 実行する場合は利用者の承認を得ている（生成物3ファイルを上書きし、`npx terser` を呼ぶため）
- [ ] 実行後の差分が、意図した変更だけである

## 3. タグマネージャーの変更（`tagm.html`）

自動検査のコマンドはない（HTML と埋め込みスクリプトを検査する仕組みがない）。

- [ ] 変更箇所以外の差分がない
- [ ] 手動確認: ブラウザで開き、開発者ツールのコンソールにエラーが出ない
- [ ] 手動確認: PC 幅とスマホ幅の両方で、変更した機能が動く
- [ ] CDN の読み込み先を変えた場合、その理由を報告している

## 4. 文章の変更（`README.md`、`docs/`、画面の文言）

- [ ] `.claude/rules/japanese-writing.md` のルールに沿っている
- [ ] ボタン名・項目名が、コードや実際の画面の表示と一致している（`grep` で照合する）
- [ ] 確認できない事実を断定していない

## 5. AI 作業設定の変更（`AGENTS.md`、`CLAUDE.md`、`.claude/`）

- [ ] `node .claude/hooks/check-claude-setup.mjs` の結果が「不合格 0件」
- [ ] 新しい Claude Code セッションで、`/memory`、`/skills`、`/hooks`、`/permissions` の表示を利用者が確かめた（実機での読み込み確認）
- [ ] 確認役は `/agents` では一覧できないため、実際に `project-reviewer` へ依頼して起動するかを確かめた
- [ ] 許可の範囲を広げていない（`bypassPermissions`、Bash の全許可などを追加していない）

## 6. 公開・本番に関わる操作

- [ ] `main` への push、`static.yml` の変更、GitHub Pages の設定変更は、その操作ごとに利用者の明示的な承認がある
